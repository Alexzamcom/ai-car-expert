# Локальная автомобильная маршрутизация Android

## Выбор движка

| Движок | Лицензия | Пригодность для этого приложения |
| --- | --- | --- |
| [Valhalla](https://github.com/valhalla/valhalla), [сборка WASM](https://github.com/adret-maps/valhalla-wasm) | MIT | Версия Valhalla 3.9 запускается в Web Worker, читает подготовленные графы с телефона и возвращает геометрию, названия и манёвры. Один формат графа для подготовки на Linux и расчёта на телефоне. |
| [GraphHopper](https://github.com/graphhopper/graphhopper) | Apache-2.0 | Автомобильные профили и ограничения есть. Встраивание текущего Java-ядра требует отдельной проверки библиотек и цепочки сборки Android, граф зависит от версии и профиля. |
| [BRouter](https://github.com/abrensch/brouter) | MIT | Зрелая мобильная доставка сегментов, упор на велосипедные профили. Для этого интерфейса пришлось бы отдельно проверять автомобильные профили и преобразование инструкций. |
| [OSRM](https://github.com/Project-OSRM/osrm-backend) | BSD-2-Clause | Используется как онлайн-резерв. Официальный серверный C++ runtime потребовал бы нативной сборки и поддержки Android ABI. |

WASM-порт зафиксирован на `3.9.0-alpha.2`. APK содержит исполняемый модуль и лицензии, а дорожные данные загружаются отдельно. Векторные тайлы, граф и адресный индекс хранятся в IndexedDB. При расчёте Worker читает граф одного подходящего региона и завершается, освобождая память. Между соседними пакетами графы пока не сшиваются. Лимиты 160 МБ на граф, 450 МБ на пакет и 16 МБ на кеш декодированного графа ограничивают загрузку. Это лимиты реализации. Фактический пик памяти на Note 9 нужно измерить с настоящим пакетом, включая карту и WebView.

## Подготовка поставщика

1. Получить разрешённый офлайн-экстракт OpenStreetMap с запасом вокруг выбранной области. Сохранить источник, дату и атрибуцию. Публикация производной базы должна соблюдать [ODbL](https://www.openstreetmap.org/copyright).
2. Собрать обычные несжатые `.gph` тайлы дорожного графа командой `valhalla_build_tiles` из `ghcr.io/valhalla/valhalla-scripted:3.9.0`. Указать локальный каталог `mjolnir.tile_dir` и пустой `mjolnir.tile_extract`. Перед использованием дорожных данных проверить манёвры и покрытие на границах экстракта.
3. Из того же экстракта изготовить векторные MBTiles (например, [tilemaker](https://github.com/systemed/tilemaker) с совместимой схемой), MapLibre-стиль с одним векторным источником и локальные PBF диапазоны Noto Sans Regular для латиницы и кириллицы. Использовать шрифты с правом распространения и включить их лицензию. Публичные тайлы OpenFreeMap для наполнения больших пакетов не скачиваются.
4. Установить `osmium==4.3.0` для Python и запустить:

   ```sh
   python scripts/prepare-offline-region.py \
       --osm region.osm.pbf --graph valhalla-tiles --mbtiles region.mbtiles \
       --style style.json --glyphs ./noto-pbf --bounds WEST SOUTH EAST NORTH \
       --out 'provider/ph:OSM_ID/10'
   ```

   Поддерживаются радиусы 10, 25, 50 и 100 км. Каждый каталог должен включать прямоугольное покрытие, которое интерфейс рисует вокруг выбранного центра для данного радиуса. Пакет может содержать запас графа вне прямоугольника. Адресный индекс строится из явно размеченных адресных точек, зданий/улиц и населённых пунктов OSM. Варианты `name:uk` и `name:ru` учитываются там, где они присутствуют в OSM. Пропуски и неточности OSM сохраняются, интерполяции номеров домов нет.
5. Разместить дерево на HTTPS с GET и CORS для приложения (`https://localhost` или публичный CORS) и без HTML-переадресаций. Имена путей берутся из идентификатора Photon `ph:OSM_ID` и радиуса, например `/ph%3AOSM_ID/10/manifest.json`. Ассеты должны передавать содержимое, совпадающее с размерами в манифесте. Сначала разместить ассеты, затем манифест. URL поставщика задаётся переменной Actions `OFFLINE_PACKAGE_PROVIDER` для APK либо в «Источник пакетов» на телефоне.

В тестовой сборке нет настроенного публичного поставщика и актуального набора Павлограда. Тестовый граф в репозитории содержит синтетические улицы и используется только в тестах. В старых регионах, скачанных предыдущими версиями, есть только векторные карты. Их можно обновить как раньше или скачать полноценный пакет. Каталог и первичный поиск населённого пункта требуют подключения. После загрузки маршрут и поиск адресов доступны внутри покрытия.

## Проверка на телефоне

1. Открыть «Офлайн-карты», найти населённый пункт, выбрать радиус, посмотреть границы и указанный размер, скачать пакет.
2. Отключить интернет и GNSS, перезапустить приложение. Открыть «Старт вручную», указать точку касанием или выбрать одно из сохранённых мест. Указать курс стоящего автомобиля и выбрать адрес либо точку назначения.
3. Запустить «Автономный · без GPS». В меню поездки менять режимы. Подложная GNSS-точка не меняет ручной старт в автономном режиме. Обычный режим в этом экране ждёт подтверждённого GPS, гибридный использует датчики при потере сигнала.
4. Проверить остановку, поворот, оба HUD и возврат к автомобилю. При неизвестной скорости дистанция может существенно отставать от действительной. Без недавних измеримых признаков движения позиция удерживается, а точные подсказки скрываются. Недостоверный GPS не запускает перестроение. После остановки можно вручную уточнить положение. Отклонение, подтверждённое последовательностью достоверных измерений или явной коррекцией, может запустить локальный пересчёт внутри пакета.
5. Отдельно измерить время холодного расчёта и пик памяти для 10/25/50/100 км, проверить актуальность дорог, GPS-восстановление и сенсорное управление в обновлённом Android System WebView на физическом Note 9. Bluetooth OBD ещё не подключён. Интерфейс независимых измерений оставлен в оценивателе.

Гироскоп измеряет повороты, а акселерометр помогает оценивать разгон и торможение. Смартфон в общем случае не может измерить пройденное автомобилем расстояние на длинной прямой с постоянной скоростью. Это экспериментальный режим.
